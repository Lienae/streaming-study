핵심 개념

프로토콜 RTSP
카메라 영상을 외부로 내보내는 프로토콜. 정확히는 영상 데이터는 RTP로 흐르고, RTSP는 세션을 제어(재생·정지)하는 역할.

서버가 카메라에서 영상을 pull하는 방식이 일반적. 기본 포트 554.
변환 HLS
HTTP Live Streaming. 브라우저가 RTSP를 이해 못하므로 변환 필요.

· .m3u8 — 플레이리스트(인덱스)
· .ts — 2~6초짜리 영상 조각
· m3u8이 실시간 갱신되어 새 ts를 가리킴 → 이게 "실시간"처럼 보이는 원리
서버 MediaMTX
RTSP → HLS 외에도 RTMP, WebRTC, SRT 등 다양한 프로토콜을 지원하는 올인원 미디어 서버.

mediamtx.yml 설정 파일 하나로 카메라 등록 + 변환 설정 가능. 테스트용으로 최적.
코덱 H.264 vs H.265
· H.264 — 브라우저 지원 완벽, 변환 불필요. 권장.
· H.265(HEVC) — 압축률 높지만 브라우저 지원 불안정 → 변환 필요.

카메라 구매 시 H.264 지원 여부 반드시 확인.

보안 인증 / 접근 제어
HLS URL을 그대로 노출하면 누구나 볼 수 있음.

· 로그인 후 토큰 발급 → URL에 포함
· 또는 Nginx 리버스 프록시로 인증 처리
네트워크 내부망 → 외부 노출
수중 카메라는 보통 유선 PoE 연결 (전원+데이터 한 케이블).

내부망에 있는 서버를 외부에서 보려면
· 포트포워딩 또는
· Nginx 리버스 프록시 설정 필요
스케일링 카메라 많아지면
MediaMTX는 단독으로 부하 한계 있음.
