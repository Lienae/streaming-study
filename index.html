핵심 개념

프로토콜

RTSP

스트리밍 세션을 제어하는 프로토콜.

주요 명령
  • SETUP
  • PLAY
  • PAUSE
  • TEARDOWN

실제 영상 데이터는 RTP가 전송한다.
기본 포트 : 554
전송

RTP

실제 영상/음성 데이터를 전송하는 프로토콜.

RTSP가 연결을 제어하고 RTP가 영상 데이터를 전달한다.

대부분 UDP 기반으로 동작한다.

예시
RTSP → PLAY 요청
RTP → 실제 영상 전송
설명 정보

SDP

영상 스트림의 정보를 설명하는 데이터.

포함 정보
  • 코덱(H264)
  • 해상도
  • FPS
  • 오디오 정보

RTSP 연결 시 먼저 전달된다.
변환

HLS

브라우저는 RTSP를 직접 재생할 수 없다.

HLS는 영상을 작은 조각으로 분할하여 전송한다.
  • .m3u8 : 플레이리스트
  • .ts : 영상 조각 파일

브라우저는 m3u8을 읽고 ts 파일을 순서대로 다운로드하며 재생한다.

장점 : 대규모 동시 접속에 유리
단점 : 지연시간 발생
서버

MediaMTX

RTSP 스트림을 받아 다양한 프로토콜로 재전송하는 스트리밍 서버.

지원 프로토콜
  • HLS
  • WebRTC
  • RTMP
  • SRT

카메라와 브라우저 사이의 중계 역할 수행
실시간

WebRTC

초저지연 실시간 스트리밍 기술.

브라우저가 MediaMTX와 직접 연결하여 영상을 수신한다.

지연시간 0.1 ~ 1초

장점
  • 거의 실시간
  • 안전 모니터링 적합
단점
  • 동시 접속 증가 시 서버 부담
코덱

H.264 vs H.265

코덱 = 영상을 압축하는 방식

H.264
  • 브라우저 호환성 우수
  • WebRTC 지원
  • 가장 많이 사용
H.265
  • 압축 효율 우수
  • 대역폭 절약
  • 브라우저 지원 제한

지연 시간 비교

방식 지연 추천
HLS 10~30초
학부모 시청
LL-HLS 2~5초
준실시간 모니터링
WebRTC 0.1~1초
실시간 모니터링

TCP vs UDP

TCP

신뢰성 우선

데이터 유실 없이 전달

  • 재전송 가능
  • 신뢰성 높음
  • 상대적으로 느림

사용 예
  • 웹 페이지
  • 파일 다운로드
  • DB 통신
UDP

속도 우선

빠르게 전달하며 일부 데이터 손실 가능

  • 재전송 없음
  • 지연 최소화
  • 패킷 유실 가능

사용 예
  • RTP
  • WebRTC
  • 실시간 스트리밍

실제 데이터 흐름

1. 브라우저 접속

2. MediaMTX에 요청

3. MediaMTX → 카메라 RTSP 연결

4. 카메라 → SDP 전달

5. 카메라 → RTP 영상 전송

6. MediaMTX

    └ WebRTC 변환

7. 브라우저 재생
